# femtic_misfit.py (module)

Engine of the data-misfit scripts `femtic_ens_misfit.py` (ensemble) and
`femtic_mod_misfit.py` (single models). It is the content of
`femtic_data_misfit.py` with the settings moved out of the module globals.

- Author: vrath (DIAS), py4mt
- Code generated by Claude Sonnet 5.5 (Anthropic), 2026-11-09 -- AI-generated, review before production use.

## Overview

`femtic_data_misfit.py` has its settings as module-level globals and chooses
between a single run and an ensemble with `RUN_MODE`. The module
`femtic_misfit.py` contains the same functions (reading and selecting the
results files, building the aligned ensemble dataset, the site-id merge, the
fit measures, the crossplot / histogram / Q-Q / curves / nRMS methods), but
the settings are an argument:

    import femtic_misfit as fm

    opts = fm.make_settings(RUN_PATHS=["./ens/m*/"], METHODS=("crossplot", "qq"),
                            OUT_DIR="./results")
    rc = fm.run_ensemble(opts)          # or fm.run_models(opts)

The scripts `femtic_ens_misfit.py` and `femtic_mod_misfit.py` hold the
settings block, collect it with a small `settings()` function and call
`run_ensemble` / `run_models`.

`femtic_data_misfit.py` was **not** changed and still works as before; the
engine now exists twice (script and module). If you want to keep a single
copy, the script can later be reduced to a thin wrapper around this module
(`RUN_MODE` -> `fm.run(opts, argv, mode)`).

## API

| Name | Meaning |
|------|---------|
| `Settings` | class with all settings as annotated class attributes (neutral defaults: `RUN_PATHS = []`, `OUT_DIR = None`, `OUT_PREFIX = None`, `NRMS_RESULTS = None`, `METHODS = ("crossplot", "histogram", "qq")`) |
| `SETTING_NAMES` | tuple with the names of all settings |
| `make_settings(**overrides)` | returns a `SimpleNamespace` with the defaults (deep copies) and the overrides applied; an unknown name raises `KeyError` |
| `run_ensemble(opts, argv=())` | one ensemble from `argv` or `opts.RUN_PATHS`; runs `"nrms"` once if requested; returns the exit code |
| `run_models(opts, argv=())` | every entry its own single run; `"nrms"` is ignored with a message |
| `run(opts, argv=(), mode="ensemble")` | `run_models` for `"single"`, else `run_ensemble` |
| `resolve_run`, `expand_paths`, `build_dataset`, `align_members`, `merge_sites_by_position`, `data_rms`, ... | the building blocks of `femtic_data_misfit.py`, unchanged |
| `process_runs(runs, opts, *, mode, out_dir, prefix)` | all selected methods for resolved runs (`mode` = `"single"` or `"ensemble"`) |
| `run_curves(ds, opts, *, out_dir, prefix, title_extra, plot_dir, search_dirs)`, `run_nrms_histogram(opts)` | methods `"curves"` and `"nrms"` |

Only the five functions that used the settings (`_curves_cfg`, `run_curves`,
`run_nrms_histogram`, `process_runs`, and the former `main`) changed their
signature; their bodies read `opts.NAME` instead of the global `NAME`.
Console messages start with `femtic_misfit:`. With matplotlib the backend is
set to `Agg` unless `opts.SHOW`.

Prefix and directory rules are the same as in the scripts: ensemble prefix
`OUT_PREFIX` or `ensemble_M<M>`, directory `OUT_DIR` or the common parent of
the members; single prefix `<run>_iter<N>`, with `OUT_PREFIX` alone for one
entry and `<OUT_PREFIX>_<run>_iter<N>` for several.

## Method (Baba 2023)

Baba (2023) proposes normalizing the residuals by both the observed and the
synthesized standard error, with M syntheses of the same model (Eqs. 10-14):

    mu      = (1/M) sum_j Z_j                          (complex mean)
    sigma   = sqrt( 1/(M-1) sum_j |Z_j - mu|^2 )       (complex modulus)
    eps_syn = sigma / sqrt(M)
    RMS1    = sqrt( 1/(2N) sum |Zobs - Zsyn|^2 / eps_obs^2 )
    RMS2    = sqrt( 1/(2N) sum |Zobs - mu|^2 / (eps_obs^2 + eps_syn^2) )

The histograms follow the paper's Fig. 10a: bars = normalized residuals,
red line = N(0, RMS^2), blue dashed lines = +/- RMS. In ensemble mode the
bars use the RMS2 normalization and the RMS1 histogram is added as an
orange step outline; in single mode (M = 1, eps_syn = 0) RMS2 equals RMS1
and only the conventional histogram is drawn.

### Assumptions and generalizations (please check)

- **Ensemble members play the role of Baba's M syntheses.** In the paper
  the M calculations are the same model discretized in M rotated coordinate
  systems, all expressed in a common coordinate system. For an ensemble of
  different models (e.g. RTO members) sigma is model spread, not
  forward-calculation uncertainty; the formulas are applied unchanged, but
  interpret RMS2 accordingly.
- **Per-part errors.** FEMTIC gives `re_err` and `im_err`; each real /
  imaginary part is normalized by its own error (the paper uses one
  eps_obs per complex element). eps_syn (from the complex modulus) is shared
  by both parts. For real-valued data types (APP_RES_AND_PHS, PT, ...)
  the formulas reduce to one real part per datum.
- **Observed data in an ensemble.** `ENSEMBLE_OBS = "mean"` averages observed
  values and errors over members (RTO-perturbed data average back to the
  original); `"first"` uses the first member.
- **RMS1 reference.** `REF_MEMBER = None` uses the ensemble mean as the
  calculated response for RMS1 (so RMS1 and RMS2 differ only by eps_syn);
  an integer uses that member's response, as Baba used one model.
- **Best iteration** is determined here from the `/data` rows only (no
  distortion, no regularization term); it may differ from FEMTIC's own
  convergence log.
- Crossplots in ensemble mode show observed vs. the ensemble-mean response.

## Fit measures

Several measures of data fit are computed for the error-normalized
residuals r, using the routines in `inverse.py` (`nrms`, `r_mae`, `r_med`,
`q95`) plus the mean of r (bias):

| Measure | Definition | Expected for r ~ N(0,1) |
|---------|------------|-------------------------|
| `nrms`  | sqrt(mean(r^2)) | 1 |
| `r_mae` | sqrt(pi/2) * mean(abs(r)) | 1 |
| `r_med` | median(abs(r)) / 0.6745 | 1 |
| `q95`   | 95th percentile of abs(r) | 1.96 |
| `mean`  | mean(r) | 0 |

`r_mae`, `r_med` and `q95` are less sensitive to outliers than `nrms`; if
they stay near their expected values while `nrms` is large, a few outliers
rather than a general misfit are the likely cause. Each is given for both
normalizations: `err` (observed error only, conventional, Baba's RMS1) and
`err+syn` (observed plus synthesized error, RMS2; ensemble only).

Where they appear:

- `<prefix>_fit_measures.txt` (switch `FIT_MEASURES`): pooled over all data
  (`ALL`) and per data type; also printed.
- `<prefix>_crossplot_stats.txt`: per panel (data type / component / part);
  columns with suffix 1 / 2 are the two normalizations (ensemble only).
- `<prefix>_hist_stats.txt`: per band (and pooled), one row per
  normalization, plus `n_out`.

The crossplot and histogram statistics use the same residuals (the RMS1
reference is the ensemble mean, or the `REF_MEMBER` response if set). The
Q-Q table keeps its own robust slope/intercept statistics.

## Site ids: one id per position

Different data types often number the same station differently; in one
real data set the MT stations are 1..48 and the VTF stations 1001..1048
(the "dummy station" trick of the FEMTIC manual). Taken literally, every
data type would be a separate "site" in the per-site table and in the
"curves" figures.

With `SITE_MERGE_BY_POSITION = True` (default) the script therefore checks
the position (`site_x`, `site_y`) of each station of each data type and gives
all rows at the same position -- within `SITE_MERGE_TOL` (default 1 m) --
the `site_id` of the **first occurrence** of that position, in the row order
of the results file (normally the impedance data). VTF 1001 becomes 1, and so
on. Consequences:

- `<prefix>_site_nrms.txt` has one line per position (nRMS over all its
  data types); the new column `also_ids` lists the other ids merged into it.
- "curves": one figure per position, with the impedance (rho, phase) and
  tipper panels together; `CURVES_SITES` (ids, `"worst"`, ...) refers to the
  merged ids; the names from `site.dat` are assigned to the merged ids.
- The crossplot, histogram, Q-Q and fit-measure results do not use site ids
  and are unchanged. Ensemble members are aligned on the original ids
  before the merging.
- The run prints the number of ids and positions and some examples
  (`1001 -> 1`).
- HTF and NMT rows (x / y are not one station position) and rows without a
  finite position keep their ids. If the same number is used for two
  different positions (e.g. MT 2 and a VTF 2 elsewhere), the later one gets a
  fresh id above the largest one, with a warning.
- `False` leaves the ids of the results file as they are.

  next call), unknown names raise `KeyError`, there is no `RUN_MODE`.
