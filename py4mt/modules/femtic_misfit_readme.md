# femtic_misfit.py (module)

Engine of the data-misfit scripts `femtic_ens_misfit.py` (ensemble) and
`femtic_mod_misfit.py` (single models). It is the content of
`femtic_data_misfit.py` with the settings moved out of the module globals.

- Author: vrath (DIAS), py4mt
- Code generated by Claude Sonnet 5.5 (Anthropic), 2026-11-09 -- AI-generated, review before production use.

## Overview

`femtic_data_misfit.py` has its settings as module-level globals and chooses
between a single run and an ensemble with `RUN_MODE`. The module
`femtic_misfit.py` contains the same functions (reading and selecting the
results files, building the aligned ensemble dataset, the site-id merge, the
fit measures, the crossplot / histogram / Q-Q / curves / nRMS / outliers methods), but
the settings are an argument:

    import femtic_misfit as fm

    opts = fm.make_settings(RUN_PATHS=["./ens/m*/"], METHODS=("crossplot", "qq"),
                            OUT_DIR="./results")
    rc = fm.run_ensemble(opts)          # or fm.run_models(opts)

The scripts `femtic_ens_misfit.py` and `femtic_mod_misfit.py` hold the
settings block, collect it with a small `settings()` function and call
`run_ensemble` / `run_models`.

`femtic_data_misfit.py` was **not** changed and still works as before; the
engine now exists twice (script and module). If you want to keep a single
copy, the script can later be reduced to a thin wrapper around this module
(`RUN_MODE` -> `fm.run(opts, argv, mode)`).

## Method (Baba 2023)

Baba (2023) proposes normalizing the residuals by both the observed and the
synthesized standard error, with M syntheses of the same model (Eqs. 10-14):

    mu      = (1/M) sum_j Z_j                          (complex mean)
    sigma   = sqrt( 1/(M-1) sum_j |Z_j - mu|^2 )       (complex modulus)
    eps_syn = sigma / sqrt(M)
    RMS1    = sqrt( 1/(2N) sum |Zobs - Zsyn|^2 / eps_obs^2 )
    RMS2    = sqrt( 1/(2N) sum |Zobs - mu|^2 / (eps_obs^2 + eps_syn^2) )

The histograms follow the paper's Fig. 10a: bars = normalized residuals,
red line = N(0, RMS^2), blue dashed lines = +/- RMS (another scale can be
chosen with `HIST_SCALE_MEASURE`). In ensemble mode the
bars use the RMS2 normalization and the RMS1 histogram is added as an
orange step outline -- but only with `SHOW_RMS2 = True` (default `False`: no
modelling error is used, so RMS2 is not shown anywhere and the bars are the
conventional RMS1 normalization); in single mode (M = 1, eps_syn = 0) RMS2
equals RMS1 and only the conventional histogram is drawn.

### Assumptions and generalizations (please check)

- **Ensemble members play the role of Baba's M syntheses.** In the paper
  the M calculations are the same model discretized in M rotated coordinate
  systems, all expressed in a common coordinate system. For an ensemble of
  different models (e.g. RTO members) sigma is model spread, not
  forward-calculation uncertainty; the formulas are applied unchanged, but
  interpret RMS2 accordingly.
- **Per-part errors.** FEMTIC gives `re_err` and `im_err`; each real /
  imaginary part is normalized by its own error (the paper uses one
  eps_obs per complex element). eps_syn (from the complex modulus) is shared
  by both parts. For real-valued data types (APP_RES_AND_PHS, PT, ...)
  the formulas reduce to one real part per datum.
- **Observed data in an ensemble.** `ENSEMBLE_OBS = "mean"` averages observed
  values and errors over members (RTO-perturbed data average back to the
  original); `"first"` uses the first member.
- **RMS1 reference.** `REF_MEMBER = None` uses the ensemble mean as the
  calculated response for RMS1 (so RMS1 and RMS2 differ only by eps_syn);
  an integer uses that member's response, as Baba used one model.
- **Best iteration** is determined here from the `/data` rows only (no
  distortion, no regularization term); it may differ from FEMTIC's own
  convergence log.
- Crossplots in ensemble mode show observed vs. the ensemble-mean response.

## Fit measures

Several measures of data fit are computed for the error-normalized
residuals r (`modules/misfit_measures.py`), using the routines in `inverse.py` (`nrms`, `r_mae`, `r_med`,
`q95`), the mean of r (bias) and its higher moments:

| Measure | Definition | Expected for r ~ N(0,1) |
|---------|------------|-------------------------|
| `nrms`  | sqrt(mean(r^2)) | 1 |
| `r_mae` | sqrt(pi/2) * mean(abs(r)) | 1 |
| `r_med` | median(abs(r)) / 0.6745 | 1 |
| `q95`   | 95th percentile of abs(r) | 1.96 |
| `mean`  | mean(r) | 0 |
| `std`   | sqrt(mean((r - mean(r))^2)) | 1 |
| `skew`  | m3 / m2^1.5 (skewness) | 0 |
| `kurt`  | m4 / m2^2 - 3 (excess kurtosis) | 0 |

`r_mae`, `r_med` and `q95` are less sensitive to outliers than `nrms`; if
they stay near their expected values while `nrms` is large, a few outliers
rather than a general misfit are the likely cause. Each is given for both
normalizations: `err` (observed error only, conventional, Baba's RMS1) and
`err+syn` (observed plus synthesized error, RMS2; only with `SHOW_RMS2 = True`
and M > 1).

The higher moments are taken about the sample mean (so a bias does not enter)
with the plain 1/n estimators of `scipy.stats.skew` / `scipy.stats.kurtosis`
(`skew = m3 / m2^1.5`, `kurt = m4 / m2^2 - 3`, `m_k = mean((r - mean(r))^k)`;
`kurt` is the EXCESS kurtosis, 0 for a Gaussian). For independent values their
standard errors are about `sqrt(6/n)` and `sqrt(24/n)`; the bias of `kurt` for
small samples is about `-6/(n+1)`, so bands with few values are only a rough
guide. `kurt > 0` = heavy tails (outliers), `kurt < 0` = light tails; `skew > 0`
= tail towards observed > calculated. Undefined values (`skew` needs n >= 3,
`kurt` n >= 4, and a non-constant sample) are `nan`.

Where they appear:

- `<prefix>_fit_measures.txt` (switch `FIT_MEASURES`): pooled over all data
  (`ALL`) and per data type; also printed.
- `<prefix>_crossplot_stats.txt`: per panel (data type / component / part);
  columns with suffix 1 / 2 are the two normalizations (ensemble only);
  of the higher moments only `skew` and `kurt` are listed.
- `<prefix>_hist_stats.txt`: per band (and pooled), one row per
  normalization, plus `n_out`.

The crossplot and histogram statistics use the same residuals (the RMS1
reference is the ensemble mean, or the `REF_MEMBER` response if set). The
Q-Q table keeps its own robust slope/intercept statistics and adds
`skew` and `kurt` of the plotted residuals (RMS2-normalized for an
ensemble with `SHOW_RMS2 = True`, else RMS1).

| `HIST_SCALE_MEASURE` | `"nrms"` | Scale s of the red curve N(0, s^2) and of the blue dashed lines at +/- s in the histograms: `"nrms"`, `"r_mae"`, `"r_med"` or `"q95"` (s = q95 / 1.96); `None` = neither is drawn |
| `SITE_MEASURES` | `"nrms"` | Per-site value(s): a name or a list of names, see below |
| `CURVES_MAP_MEASURE_RANGE` | `None` | `(lo, hi)` of the colour scale of the site map if the first entry of `SITE_MEASURES` is not `"nrms"` (for nRMS: `CURVES_MAP_NRMS_RANGE`); `None` = smallest / largest value, for signed measures symmetric about 0 |

Entries of `PANEL_MEASURES`:

- the measures `nrms`, `r_mae`, `r_med`, `q95`, `mean`, `std`, `skew`, `kurt`
  (also accepted: `rms`, `rmae`, `rmed`, `bias`);
- `n` (number of values), `slope` and `icpt` (quartile line of the normal Q-Q
  plot; also `intercept`);
- `n_out` (histogram and Q-Q only: values outside +/- `HIST_LIMIT` / `QQ_LIMIT`,
  written only if > 0) and `out_pct` (Q-Q only: dots outside the envelope).

In a list for all figures an entry that does not apply to a kind of figure is
left out there; in the list of that one kind it is an error. With RMS2 shown
(`SHOW_RMS2`), the measures and `slope` are written twice (suffix 1 / 2), while
`icpt` and `n_out` refer to the plotted variant. An unknown name stops the run
with a message. Long lists need a smaller `PANEL_MEASURES_FONTSIZE` or larger
panels.

```python
PANEL_MEASURES = {"crossplot": ["n", "nrms", "r_med"],
                  "histogram": ["n", "nrms", "r_mae", "r_med", "skew", "n_out"],
                  "qq": ["slope", "icpt", "out_pct"]}
HIST_SCALE_MEASURE = "r_med"
SITE_MEASURES = ["r_med", "nrms"]
```

`SITE_MEASURES`:

- method `"outliers"`: one analysis per entry (table, CSV and figure; the file
  names of entries other than `nrms` get the suffix `_<measure>`, e.g.
  `<prefix>_site_outliers_r_med.txt`);
- method `"curves"`: all entries appear in the figure title; the FIRST entry
  colours the site map, orders `CURVES_SITE_ORDER = "worst"` / `"best"` and
  selects `CURVES_SITES = "outliers"`;
- `<prefix>_site_nrms.txt` gets one column per further entry;
- `mean`, `skew` and `kurt` can be negative: worst / best go by the absolute
  value, the map uses `coolwarm` about 0 (unless `CURVES_MAP_CMAP` /
  `CURVES_MAP_MEASURE_RANGE` are set) and `OUTLIER_LOG10` is ignored.

A site value is computed from the residuals of that site only. With few values,
`std`, `skew` and `kurt` in particular scatter strongly (`skew` needs n >= 3,
`kurt` n >= 4; otherwise the value is `nan`).

Title fields of "curves" (`FIGURE_TITLE`): `{fit}` (all entries of
`SITE_MEASURES`, e.g. `rMED = 1.12, nRMS = 1.35`) and one field per measure
(`{nrms}`, `{r_med}`, ...; `n/a` for observed-only).

The routines are in `modules/misfit_measures.py` (see
`misfit_measures_readme.md`).

## Site ids: one id per position

Different data types often number the same station differently; in one
real data set the MT stations are 1..48 and the VTF stations 1001..1048
(the "dummy station" trick of the FEMTIC manual). Taken literally, every
data type would be a separate "site" in the per-site table and in the
"curves" figures.

With `SITE_MERGE_BY_POSITION = True` (default) the script therefore checks
the position (`site_x`, `site_y`) of each station of each data type and gives
all rows at the same position -- within `SITE_MERGE_TOL` (default 0.001 km = 1 m) --
the `site_id` of the **first occurrence** of that position, in the row order
of the results file (normally the impedance data). VTF 1001 becomes 1, and so
on. Consequences:

- `<prefix>_site_nrms.txt` has one line per position (nRMS over all its
  data types); the new column `also_ids` lists the other ids merged into it.
- "curves": one figure per position, with the impedance (rho, phase) and
  tipper panels together; `CURVES_SITES` (ids, `"worst"`, ...) refers to the
  merged ids; the names from `site.dat` are assigned to the merged ids.
- The crossplot, histogram, Q-Q and fit-measure results do not use site ids
  and are unchanged. Ensemble members are aligned on the original ids
  before the merging.
- The run prints the number of ids and positions and some examples
  (`1001 -> 1`).
- HTF and NMT rows (x / y are not one station position) and rows without a
  finite position keep their ids. If the same number is used for two
  different positions (e.g. MT 2 and a VTF 2 elsewhere), the later one gets a
  fresh id above the largest one, with a warning.
- `False` leaves the ids of the results file as they are.

## Site outliers (method `"outliers"`)

Which sites fit much worse (or better) than the others? For every site the nRMS of
`<prefix>_site_nrms.txt` is used: the conventional (RMS1) normalization over the real and
imaginary parts of all data of the site; for an ensemble of the ensemble-mean response, or
of `REF_MEMBER`. The sites whose nRMS is **outside the limits of the distribution of these
site values** are the outliers. Add `"outliers"` to `METHODS`.

| `OUTLIER_METHOD` | Limits (k = `OUTLIER_SIGMA`, default 2) | Centre, spread (for z) |
|---|---|---|
| `"quantile"` (default) | the quantiles at the tail levels of a normal distribution at -k and +k sigma; for k = 2 the 2.275 % and 97.725 % quantiles of the site nRMS values (numpy's linear interpolation) | median, (hi - lo) / (2 k) |
| `"sigma"` | mean -+ k std (ddof = 1) | mean, std |
| `"mad"` | median -+ k * 1.4826 * MAD (a robust sigma) | median, 1.4826 MAD |

A site is outside if its nRMS is **strictly** below the lower or above the upper limit.
`OUTLIER_SIDE` = `"both"` (default), `"high"` (poorly fitted sites only) or `"low"`.
`OUTLIER_LOG10 = True` does the `"sigma"` / `"mad"` statistics on log10(nRMS) (nRMS is
positive and skewed; the limits are given back as nRMS, z is in log10 units); it has no effect
on `"quantile"`. `OUTLIER_MIN_N` leaves out sites with fewer residual values. A site without an
nRMS (no datum with a positive error) is never used or flagged; with fewer than 3 usable sites
there are no limits and nothing is flagged.

**What the default does and does not say.** The quantile limits always put the smallest and
the largest site nRMS outside (for 3 or more sites, unless tied), and about 2.3 % of the
sites on each side for many sites, whatever the data. They name the *extreme* sites; they do
not say that these are exceptional. Whether a site really stands out is better judged with
`"mad"` (not inflated by the outliers) or `"sigma"` (the standard deviation grows with a very
bad site, which can hide the next one). On a synthetic test set with one very bad and one
very good site, `"quantile"` flagged both and some ordinary extremes as well, `"sigma"` only the
worst one, and `"mad"` six sites; the real behaviour depends on your data.

**Other measures.** The text above is written for nRMS, the default. With
`SITE_MEASURES` the same analysis is made for every measure listed there (for
the signed measures `mean`, `skew`, `kurt` both tails are of interest, and
`OUTLIER_LOG10` is ignored); table columns, labels and the file suffix
`_<measure>` follow the measure. See "Choosing the plotted measures".

Output (the site names come from `site.dat` as for `"curves"`: `CURVES_SITE_DAT`,
`CURVES_SITE_MATCH`, `CURVES_SITE_ID_OFFSET`, `CURVES_SITE_TOL`):

- `<prefix>_site_outliers.txt` (and the console): a few comment lines (how the limits were
  found, the limits, the number of sites outside), then a table of the sites outside, largest
  nRMS first: `rank` (1 = largest nRMS of all used sites), `site_id`, `name`, `site_x`,
  `site_y`, `n` (residual values), `nrms`, `z` = (nRMS - centre) / spread (see the table above)
  and `side` (`high` / `low`).
- `<prefix>_site_outliers.csv`: one comment line, then every site (`site_id,name,site_x,site_y,n,
  nrms,flag`); `flag` is `high`, `low`, empty (inside) or `unused`. Both text files only
  with `WRITE_STATS`.
- `<prefix>_site_outliers.<fmt>` (`PLOT_FORMATS`, `PLOT_DIR`; `OUTLIER_PLOT = False` switches it
  off): the nRMS of every used site in the order of the site ids, grey inside the limits,
  vermillion triangles up above the upper limit, blue triangles down below the lower one (the
  first 40 sites of the table are named), the limits dashed and the centre dotted, and the
  histogram of the site nRMS values at the right on the same axis (log axis with `OUTLIER_LOG10`).
  `FIGURE_TITLE` accepts an `"outliers"` entry.
- `CURVES_SITES = "outliers"` (method `"curves"`): the response curves of exactly these sites,
  one file per site, largest nRMS first (same `OUTLIER_*` settings).

## Site map in the curves figures

`CURVES_MAP = True` adds a small map of the sites to every "curves" figure (it is off by default, and then
all output is as before).

- **What it shows.** All sites of the data set (not only those in `CURVES_SITES`) as points, the site of the figure
  marked by a larger marker with a dark ring. The colour is the site nRMS, the same number as in the title and in
  `<prefix>_site_nrms.txt` (conventional RMS1, all data types of a position pooled; for an ensemble against the
  ensemble mean or `REF_MEMBER`). The colour scale is the same on every page (smallest / largest site nRMS, or
  `CURVES_MAP_NRMS_RANGE`), so the pages can be compared; set a range such as `(0.5, 3.0)` if one outlier
  squeezes the rest. The default ramp is one hue (blue), light for a small and dark for a large nRMS, and starts
  at a medium blue so that a good site is still visible on the white page.
- **Coordinates.** `site_x` / `site_y` as stored in the results file: model coordinates in metres relative to the
  model origin, shown in km (not UTM). Equal scale in both directions; the window is never flatter (or narrower)
  than 0.4 : 1, so that a profile gets white space around it instead of becoming a sliver. `CURVES_MAP_TICKS =
  False` draws the frame only, without any ticks or labels.
- **Placement.** `"right"` / `"left"` give the map its own column, `CURVES_MAP_SIZE` cm wide, next to the
  panels; `"top"` / `"bottom"` (also `"above"` / `"below"`) give it an own row, `CURVES_MAP_SIZE` cm high, above /
  below the panels and across their whole width (the figure gets higher, the map is centred in the row). In both
  cases the map is outside the data plots. The four corner names put it as an inset into the last (right) or
  first (left) panel; it is drawn on top of the curves with a white backdrop and keeps its size whatever the panel
  size. Do not put the legend (`CURVES_LEGEND_LOC`) into the same corner; the default `"below"` is out of the way.
  The inset is `CURVES_MAP_SIZE` square, and lower for a flat window (a profile). `CURVES_MAP_SIZE` is in cm
  (default 4.3 cm), as are the sizes of the figure (`CURVES_PANEL_SIZE`).
- **Observed only.** With `CURVES_OBSERVED_ONLY` there is no nRMS in the title and none in the map: the points
  are grey, there is no colour bar, the current site is still marked.
- **Sites without data for the map.** A site without a finite position (for example HTF / NMT rows, which carry no
  station position) is left out; if the current site is one of them, the map is drawn without the marker. If no
  site has a position, there is a message and no map; the figures themselves are written as usual. A site without
  an nRMS is drawn as a hollow circle.
- **Checks.** `CURVES_MAP_PLACEMENT`, `CURVES_MAP_AXES`, `CURVES_MAP_CMAP`, `CURVES_MAP_SIZE`,
  `CURVES_MAP_MARKER_SIZE` and `CURVES_MAP_NRMS_RANGE` are checked when the method starts (message, return code 1);
  while `CURVES_MAP` is `False` they are not looked at.
- **Other measures.** If the first entry of `SITE_MEASURES` is not `"nrms"`, the map shows that measure
  (colour scale: `CURVES_MAP_MEASURE_RANGE` instead of `CURVES_MAP_NRMS_RANGE`); signed measures
  (`mean`, `skew`, `kurt`) use `coolwarm`, symmetric about 0 by default. What is said above about the site
  nRMS then holds for that measure.
