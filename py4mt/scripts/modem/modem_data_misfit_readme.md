# modem_data_misfit.py

Data-misfit diagnostics for ModEM observed/calculated data file pairs,
modelled directly on `femtic_data_misfit.py` (Claude Sonnet 5,
2026-09-18..21d).

- Author: vrath (DIAS), py4mt
- Code generated by Claude Sonnet 5 (Anthropic), 2026-09-26 -- AI-generated,
  review before production use.
- New library routines this script depends on were added to
  `modules/modem.py` on the same date: `read_data_rows`, `read_data_calc`,
  `match_data_rows`, `read_data_misfit`, `modem_is_real_only_datatype`
  (see `modem_readme.md`).

## Why ModEM needs one more step than FEMTIC

FEMTIC's `results_iterN.h5` already bundles the OBSERVED value/error and
the CALCULATED (forward) response for every datum in one file per
iteration -- `femtic.read_results_data()` reads that directly.

ModEM instead writes the observed data and the calculated (forward-
response) data to two **separate**, identically-formatted ASCII files: the
observed data file (fixed for a given inversion) and a calculated/response
data file (one per NLCG iteration, or one for a single forward run). This
script therefore needs a matching step FEMTIC does not: `modem.py` gained
three routines for it (2026-09-26):

| Function | Role |
|---|---|
| `modem.read_data_rows(file)` | Parse one ModEM data file: block-aware (tracks each data block's DataType from its `>` header), and tells real-valued from complex rows apart by **column count** (10 vs. 11) rather than guessing from the component-code text. |
| `modem.read_data_calc(file)` | Same reader, named for a calculated/response file (identical format). |
| `modem.match_data_rows(rows_a, rows_b)` | Match two `read_data_rows()` outputs by `(period, site, component)`. |
| `modem.read_data_misfit(obs, calc)` | Read an observed/calculated pair and combine them into one per-datum table -- the ModEM analogue of `femtic.read_results_data()`'s `/data` rows. |

Once that table exists, everything downstream -- dataset building (ensemble
alignment/averaging), panel construction, the three plot methods, fit
measures, and text-table output -- is **unchanged** from
`femtic_data_misfit.py`; only the run-resolution and dataset-building
sections at the top of the script differ. See "Differences from
femtic_data_misfit.py" in the script's own docstring for the itemised list.

## Overview

Three methods, selected with `METHODS` (default: all three) -- identical
to `femtic_data_misfit.py`:

1. **crossplot** -- observed vs. calculated scatter plots, one panel per data
   type / component (Re and Im separately for complex types), log10
   frequency as colour, 1:1 line, n and nRMS per panel.
2. **histogram** -- normalized-residual histograms in frequency (or period)
   bands, after Baba (2023). One figure per data type (or per data type and
   component, `HIST_BY_COMPONENT`); first panel pools all bands, then one
   panel per band. Default: 2 bands per decade (`HIST_BANDS_PER_DECADE`),
   `HIST_BAND_AXIS = "frequency"` or `"period"`; bands are anchored at
   whole decades; bands with fewer than `HIST_MIN_N` values are skipped.
3. **qq** -- normal Q-Q plots of the same normalized residuals, in the same
   kind of frequency/period bands (`QQ_*` settings, default 2 per decade,
   pooled panel first). Per panel: sample quantiles vs. theoretical N(0,1)
   quantiles; black line = ideal N(0,1) (calibrated errors); red dashed =
   robust quartile line (slope > 1: misfit larger than the stated errors,
   < 1: errors overestimated; intercept = bias); gray band = pointwise
   95% confidence envelope (`QQ_CONFIDENCE`) around the quartile line. In
   ensemble mode the dots are RMS2-normalized with the RMS1-normalized dots
   in orange (slope1 / slope2 in the table); in single mode only the
   conventional residuals are shown. `QQ_EQUAL_AXES = True` gives square
   panels with the ideal line at 45 degrees.

## Fit measures

Unchanged from `femtic_data_misfit.py`, via `inverse.py` (`nrms`, `r_mae`,
`r_med`, `q95`) plus the mean of the error-normalized residuals r (bias):

| Measure | Definition | Expected for r ~ N(0,1) |
|---------|------------|-------------------------|
| `nrms`  | sqrt(mean(r^2)) | 1 |
| `r_mae` | sqrt(pi/2) * mean(abs(r)) | 1 |
| `r_med` | median(abs(r)) / 0.6745 | 1 |
| `q95`   | 95th percentile of abs(r) | 1.96 |
| `mean`  | mean(r) | 0 |

Each is given for both normalizations: `err` (observed error only,
conventional, Baba's RMS1) and `err+syn` (observed plus synthesized error,
RMS2; ensemble only). Output files: `<prefix>_fit_measures.txt`,
`<prefix>_crossplot_stats.txt`, `<prefix>_hist_stats.txt` -- same naming and
layout as `femtic_data_misfit.py`.

## Run resolution (the ModEM-specific part)

A "run" is now an `(obs, calc)` pair, not a single results file.

### `RUN_PATHS`

`List[Tuple[str, str]]` -- `(observed file, calculated file/dir/glob)`
pairs (overridden by `argv`, given as flat `obs1 calc1 obs2 calc2 ...`).

- **`calc` is an exact file**: used as-is, no iteration ambiguity.
- **`calc` is a directory**: searched with `CALC_PATTERN` (default
  `"*_NLCG_*.dat"`, ModEM's usual NLCG-iteration naming -- **flagged,
  unverified against your actual output naming**, exactly as
  `modem_data_split_readme.md` flags the same assumption; edit
  `CALC_PATTERN` to match). `ITERATION` then picks one candidate:
  `"best"` (lowest overall error-normalized RMS against `obs`, default),
  `"last"` (highest iteration number parsed from the file name -- first
  tries `NLCG_037`-style naming, then falls back to the last run of
  digits in the file name), or an integer (exact match).
- **`calc` is a glob pattern**: same candidate/iteration handling, without
  the directory search.
- **`obs` is itself a glob** (e.g. an RTO ensemble's per-member observed
  files): `calc` must also be a glob, matching the *same count*; the two
  sorted lists are zipped pairwise into that many `(obs, calc)` runs
  (`expand_run_pairs()`). Useful for `RUN_MODE = "ensemble"` with many
  independent members, each contributing one observed/calculated pair.

### `KEY_ROUND`

Decimal places `period` is rounded to when matching an observed row to a
calculated row (`modem.match_data_rows`); default 8, matching the
convention already used for NRMS matching in `modem_data_split.py`.

### Two run modes (`RUN_MODE`, or first command-line word)

- **single** -- every `(obs, calc)` pair is processed **on its own** (after
  `expand_run_pairs()`); they do *not* form an ensemble. A pair that
  cannot be read is reported and skipped; the exit code is then 1.
- **ensemble** -- all pairs together form one ensemble; the chosen
  calculated response of each pair is one member (M members). Rows are
  matched by `(datatype, site, component, frequency)`; rows missing in any
  member, or with a non-finite calculated value in any member, are
  dropped.

## Usage

```
python modem_data_misfit.py                                  # config block
python modem_data_misfit.py single   obs1.dat calc1.dat obs2.dat calc2.dat
python modem_data_misfit.py ensemble obs1.dat calc1.dat obs2.dat calc2.dat
```

`modem.py` and `inverse.py` (fit measures; it imports `aniso`) must be
importable; if `PY4MTX_ROOT` is set, `$PY4MTX_ROOT/py4mt/modules` and
`.../scripts` are added to `sys.path`.

Output location: `OUT_DIR = None` (default) writes into the run directory
-- single: the directory of the chosen calculated file; ensemble: the
common parent directory of the member calculated files. A string forces
one directory for everything (file names stay distinct through the
prefix). Output files, prefix = `<calcfile>_iter<N>` (single) or
`ensemble_M<M>` (ensemble); `OUT_PREFIX` replaces it (prepended instead
for several singles), exactly as in `femtic_data_misfit.py`.

## Differences from femtic_data_misfit.py

- A "run" is an `(obs, calc)` pair, not a single results file; `RUN_PATHS`
  is a list of tuples, not bare paths (see "Run resolution" above).
- Real-valued vs. complex rows are told apart by column count (10 vs. 11)
  while parsing (`modem.read_data_rows()`), not guessed from the
  component-code text; `modem.modem_is_real_only_datatype()` (case- and
  separator-insensitive) replaces the hardcoded `REAL_ONLY_TYPES` tuple
  membership test used in `build_panels()`.
- ModEM gives one error per datum, applied to both the real and imaginary
  part (`modem.read_data_misfit()`); FEMTIC's separate `re_err`/`im_err`
  become identical here (`im_err` is a copy of `re_err`).
- `KEY_ROUND` (period-rounding tolerance for obs/calc row matching) has no
  FEMTIC equivalent -- FEMTIC's rows are already matched inside one file.
- `expand_run_pairs()` (matching-glob pairing for many independent
  obs/calc pairs, e.g. an RTO ensemble) has no FEMTIC equivalent; FEMTIC's
  `expand_paths()` only expands single-path globs.
- Dataset building (`build_dataset`, `_row_keys`) uses string keys
  (datatype name, site code, component code) instead of FEMTIC's integer
  codes -- ModEM data types and components are inherently string-labelled
  (from the file's `>` headers), with no compact integer encoding to
  translate to/from.
- Everything else (panels, crossplot/histogram/Q-Q plotting, fit measures,
  table formatting, the `_save`/`_write`/`process_runs`/`main` driver) is
  unchanged.

## Assumptions and generalizations (please check)

Carried over from `femtic_data_misfit.py`, plus the ModEM-specific ones
flagged above and in the script's own docstring:

- **Ensemble members play the role of Baba's M syntheses.** For an
  ensemble of different models (e.g. RTO members) the resulting sigma is
  model spread, not forward-calculation uncertainty; the formulas are
  applied unchanged (see `femtic_data_misfit_readme.md`), interpret RMS2
  accordingly.
- **Canonical DataType spelling.** `MODEM_REAL_ONLY_DATATYPES` /
  `MODEM_COMPLEX_DATATYPES` in `modem.py` assume the `>` header's DataType
  reads `Full_Impedance`, `Off_Diagonal_Impedance`,
  `Full_Vertical_Components`, `Full_Interstation_TF`,
  `Off_Diagonal_Rho_Phase`, `Phase_Tensor` (the six names listed in
  `read_data_jac()`'s docstring) -- `modem_is_real_only_datatype()` is
  case/separator-insensitive but still needs the base spelling to match.
- **`CALC_PATTERN` default (`"*_NLCG_*.dat"`).** Flagged as unverified in
  `modem_data_split_readme.md` for the same reason -- ModEM itself has no
  fixed naming convention for forward-response files; edit to match your
  actual output.
- **"Best" iteration** is determined from the matched rows' overall
  error-normalized RMS only; may differ from ModEM's own `.log` nRMS
  (see `modem_plot_rms.py`).
- Crossplots in ensemble mode show observed vs. the ensemble-mean response.

## Verification

- `ast.parse()` passes; no non-ASCII characters in the source (both
  `modem_data_misfit.py` and the `modem.py` additions).
- netCDF4/numba/h5py were not installable in the authoring environment.
  `modem.py`'s new routines were smoke-tested directly (netCDF4/numba
  stubbed, since neither is used by these routines) against synthetic
  two-datatype (Full_Impedance + Phase_Tensor), two-site, three-period
  observed/calculated file pairs: column-count-based real/complex
  detection, block-header DataType tracking, row matching (including an
  unmatched extra calculated row and a malformed line), and the
  shared-error convention were all checked.
- `modem_data_misfit.py` itself was then run end-to-end (matplotlib's
  "Agg" backend, netCDF4/numba stubbed as above) against a larger
  synthetic dataset (2 data types x 4/4 components x 3 sites x 8 periods):
  - **single mode**, `ITERATION = "best"`, `calc` given as a directory
    containing four candidate `..._NLCG_010/020/030/040.dat` files with
    known, different biases -- confirmed the file with the smallest
    injected bias (0.02) was selected as "best", and its iteration number
    (30) appears correctly in plot titles and the `_runs.txt` table.
  - **ensemble mode**, 4 members via matching `obs`/`calc` globs
    (`expand_run_pairs()`) -- confirmed M=4 in the dataset summary, RMS1
    vs. RMS2 both reported (`has_syn = True`), and all three methods'
    plots and tables were written.
  - All crossplot/histogram/Q-Q PDF files were confirmed non-empty and
    (for one crossplot and one Q-Q figure) rendered to PNG and inspected:
    panel layout, 1:1/ideal lines, colour bar, per-band titles and the
    run-name/iteration annotation ("single_dir, iteration 30") all
    appeared as expected, with the observed-vs-calculated offset matching
    the synthetic bias injected into the test data.
- **Not yet run against real ModEM output.**
