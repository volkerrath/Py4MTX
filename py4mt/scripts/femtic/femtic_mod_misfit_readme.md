# femtic_mod_misfit.py

Data-misfit diagnostics for **single** FEMTIC models / runs
(`results_iterN.h5`). Single-model half of `femtic_data_misfit.py` ("mod"
family, with `femtic_mod_plot_slice.py`, `femtic_mod_plot_bh.py`).

- Author: vrath (DIAS), py4mt
- Code generated by Claude Sonnet 5.5 (Anthropic), 2026-11-09 -- AI-generated, review before production use.

## Overview

Every entry of `RUN_PATHS` (run directories, results files, or glob patterns;
command-line arguments override them) is processed **on its own**; they do not
form an ensemble. One set of figures and tables is written per run, for the
iteration given by `ITERATION` (`"best"` = smallest error-normalized RMS of the
`/data` rows, `"last"`, or an integer; ignored if a results file is given
directly). A run that cannot be read is reported and skipped; the return code is
then 1.

Methods (`METHODS`):

1. **crossplot** -- observed vs. calculated, one panel per data type /
   component (Re and Im separately for complex types), log10 frequency as colour.
2. **histogram** -- normalized-residual histograms in frequency (or period)
   bands, after Baba (2023). For one model there is no synthesized error
   (M = 1, eps_syn = 0), so RMS2 = RMS1 and only the conventional histogram is
   drawn.
3. **qq** -- normal Q-Q plots of the same residuals, in the same bands.
4. **curves** (optional) -- observed data with errors against the calculated
   response, one figure per site.

The ensemble method `"nrms"` (nRMS histogram of all scanned members) needs an
ensemble; it is ignored here with a message. Use `femtic_ens_misfit.py` for it,
and for RMS2, for the member curves, and for an ensemble in general.

## Usage

    python femtic_mod_misfit.py                         # settings block
    python femtic_mod_misfit.py ./run01/ ./run02/       # two runs, separately
    python femtic_mod_misfit.py "./runs/run_*/"         # glob: one set each
    python femtic_mod_misfit.py ./run01/results_iter25.h5   # a results file

`femtic.py`, `inverse.py` (and `aniso.py`) and `femtic_misfit.py` must be
importable; if `PY4MTX_ROOT` is set, `$PY4MTX_ROOT/py4mt/modules` and
`.../scripts` are added to `sys.path`. Method `"curves"` needs `data_viz.py`.

Output per run (directory = `OUT_DIR`, or the directory of the chosen results
file; figures in `PLOT_DIR` if set):

- prefix = `<run>_iter<N>`; `OUT_PREFIX` replaces it if only one run is given
  and is prepended (`<OUT_PREFIX>_<run>_iter<N>`) if there are several, so the
  runs do not overwrite each other
- `<prefix>_crossplot_<DATATYPE>.*`, `<prefix>_hist_<GROUP>.*`,
  `<prefix>_qq_<GROUP>.*`
- `<prefix>_crossplot_stats.txt`, `<prefix>_hist_stats.txt`,
  `<prefix>_qq_stats.txt`, `<prefix>_fit_measures.txt`, `<prefix>_runs.txt`
- `"curves"`: `<prefix>_curves.pdf` (or `<prefix>_curves/<prefix>_curves_site<ID>.<ext>`)
  and `<prefix>_site_nrms.txt`

## Differences to femtic_data_misfit.py

- No `RUN_MODE` and no `single` / `ensemble` word on the command line; this
  script always treats every entry as a single run (`RUN_MODE = "single"` of the
  original).
- No ensemble settings: `ENSEMBLE_OBS`, `REF_MEMBER`, `NRMS_*`, and the
  `CURVES_` settings for the member layers (`CURVES_ENS_MODE`,
  `CURVES_MAX_CURVES`, `CURVES_SUBSAMPLE`, `CURVES_MEMBER_ALPHA`,
  `CURVES_MEDIAN`, `CURVES_BAND_PCT`, `CURVES_DENSITY_*`, `CURVES_SEED`).
  A stray uppercase name in the settings block is reported.
- The settings are read by `settings()` and handed to
  `femtic_misfit.run_models()`.

## Fit measures

Several measures of data fit are computed for the error-normalized
residuals r, using the routines in `inverse.py` (`nrms`, `r_mae`, `r_med`,
`q95`) plus the mean of r (bias):

| Measure | Definition | Expected for r ~ N(0,1) |
|---------|------------|-------------------------|
| `nrms`  | sqrt(mean(r^2)) | 1 |
| `r_mae` | sqrt(pi/2) * mean(abs(r)) | 1 |
| `r_med` | median(abs(r)) / 0.6745 | 1 |
| `q95`   | 95th percentile of abs(r) | 1.96 |
| `mean`  | mean(r) | 0 |

`r_mae`, `r_med` and `q95` are less sensitive to outliers than `nrms`; if
they stay near their expected values while `nrms` is large, a few outliers
rather than a general misfit are the likely cause. Each is given for both
normalizations: `err` (observed error only, conventional, Baba's RMS1) and
`err+syn` (observed plus synthesized error, RMS2; ensemble only).

Where they appear:

- `<prefix>_fit_measures.txt` (switch `FIT_MEASURES`): pooled over all data
  (`ALL`) and per data type; also printed.
- `<prefix>_crossplot_stats.txt`: per panel (data type / component / part);
  columns with suffix 1 / 2 are the two normalizations (ensemble only).
- `<prefix>_hist_stats.txt`: per band (and pooled), one row per
  normalization, plus `n_out`.

The crossplot and histogram statistics use the same residuals. The
Q-Q table keeps its own robust slope/intercept statistics.

## Site ids: one id per position

Different data types often number the same station differently; in one
real data set the MT stations are 1..48 and the VTF stations 1001..1048
(the "dummy station" trick of the FEMTIC manual). Taken literally, every
data type would be a separate "site" in the per-site table and in the
"curves" figures.

With `SITE_MERGE_BY_POSITION = True` (default) the script therefore checks
the position (`site_x`, `site_y`) of each station of each data type and gives
all rows at the same position -- within `SITE_MERGE_TOL` (default 1 m) --
the `site_id` of the **first occurrence** of that position, in the row order
of the results file (normally the impedance data). VTF 1001 becomes 1, and so
on. Consequences:

- `<prefix>_site_nrms.txt` has one line per position (nRMS over all its
  data types); the new column `also_ids` lists the other ids merged into it.
- "curves": one figure per position, with the impedance (rho, phase) and
  tipper panels together; `CURVES_SITES` (ids, `"worst"`, ...) refers to the
  merged ids; the names from `site.dat` are assigned to the merged ids.
- The crossplot, histogram, Q-Q and fit-measure results do not use site ids
  and are unchanged. Ensemble members are aligned on the original ids
  before the merging.
- The run prints the number of ids and positions and some examples
  (`1001 -> 1`).
- HTF and NMT rows (x / y are not one station position) and rows without a
  finite position keep their ids. If the same number is used for two
  different positions (e.g. MT 2 and a VTF 2 elsewhere), the later one gets a
  fresh id above the largest one, with a warning.
- `False` leaves the ids of the results file as they are.

## Verification

- Syntax and ASCII check of the three new files; `femtic`, `inverse`,
  `data_viz`, `femtic_viz` and `femtic_misfit` import in a clean interpreter
  (`python -I`).
- h5py is not installable in the authoring environment, so
  `femtic.read_results_data` was replaced by a synthetic stand-in (pickle files
  named `results_iterN.h5`; MT, APP_RES_AND_PHS and VTF rows with the VTF
  stations numbered 1001.., 6 sites x 8 frequencies, 3 iterations per run;
  8 ensemble members and 2 single runs). The real `femtic.py`, `inverse.py`,
  `data_viz.py` and `femtic_viz.py` were used otherwise.
- **Equivalence with `femtic_data_misfit.py`** (`RUN_MODE = "single"`, the
  unchanged script on the same stand-in data and settings): two single runs,
  methods crossplot, histogram, qq: 10 tables identical byte for byte and 18
  PNG figures identical pixel for pixel, the same file names.
- List of three entries with one non-existent path and `OUT_PREFIX` set:
  the bad path is skipped (return code 1, as in the original), the other two
  runs give 8 tables and 12 figures identical to the original, with the prefix
  `<OUT_PREFIX>_<run>_iter<N>`; `"nrms"` in `METHODS` is ignored with a
  message (the original would have made the nRMS histogram as well). A single
  entry with `OUT_PREFIX` gives exactly `<OUT_PREFIX>_*`; a path on the command
  line overrides `RUN_PATHS`.
- **Not run against real `results_iterN.h5` files** (no h5py here).
