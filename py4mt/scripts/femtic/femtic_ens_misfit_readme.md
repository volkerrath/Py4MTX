# femtic_ens_misfit.py

Data-misfit diagnostics for an **ensemble** of FEMTIC runs (`results_iterN.h5`).
Ensemble half of `femtic_data_misfit.py` ("ens" family, with
`femtic_ens_post.py`, `femtic_ens_plot_slices.py`, `femtic_ens_plot_bh.py`).

- Author: vrath (DIAS), py4mt
- Code generated by Claude Sonnet 5.5 (Anthropic), 2026-11-09 -- AI-generated, review before production use.

## Overview

All entries of `RUN_PATHS` (run directories, results files, or glob patterns;
command-line arguments override them) together form **one ensemble**. In each
run the iteration given by `ITERATION` (`"best"` = smallest error-normalized
RMS of the `/data` rows, `"last"`, or an integer) is one member. Rows are
matched across the members by (datatype, site_id, component, frequency); rows
missing in a member or with a non-finite calculated value in any member are
dropped. A member that cannot be read is reported and skipped.

Methods (`METHODS`):

1. **crossplot** -- observed vs. ensemble-mean response, one panel per data type
   / component.
2. **histogram** -- normalized-residual histograms in frequency (or period)
   bands, after Baba (2023): bars = RMS2 normalization (observed + synthesized
   error, the synthesized error being the spread of the members), orange step
   outline = conventional RMS1.
3. **qq** -- normal Q-Q plots of the same residuals (RMS2 dots, RMS1 in orange).
4. **curves** (optional) -- response curves per site; the members are shown as
   curves, as a density, or as percentile bands (`CURVES_ENS_MODE`).
5. **nrms** -- histogram of the best nRMS of all scanned members (accepted and
   rejected), from the results `.npz` of `femtic_ens_post.py`.

RMS2 needs M > 1; with a single member RMS2 = RMS1.

The same code does the work in `femtic_data_misfit.py` (`RUN_MODE = "ensemble"`)
and here; the difference is only that the settings of this script do not have
`RUN_MODE`, and that the engine is in `modules/femtic_misfit.py`, shared with
`femtic_mod_misfit.py` (single models).

## Usage

    python femtic_ens_misfit.py                              # settings block
    python femtic_ens_misfit.py "./ens/member_*/"            # glob (quote it)
    python femtic_ens_misfit.py ./m01/ ./m02/ ./m03/         # explicit members

`femtic.py` (and `ensembles.py`), `inverse.py` (and `aniso.py`) and
`femtic_misfit.py` must be importable; if `PY4MTX_ROOT` is set,
`$PY4MTX_ROOT/py4mt/modules` and `.../scripts` are added to `sys.path`.
Method `"curves"` needs `data_viz.py`, method `"nrms"` needs `femtic_viz.py`.
The return code is 0 on success and 1 if no usable member was found or a file
could not be read.

Output (prefix = `OUT_PREFIX`, or `ensemble_M<M>`; directory = `OUT_DIR`, or the
common parent directory of the members; figures in `PLOT_DIR` if set):

- `<prefix>_crossplot_<DATATYPE>.*`, `<prefix>_hist_<GROUP>.*`,
  `<prefix>_qq_<GROUP>.*`
- `<prefix>_crossplot_stats.txt`, `<prefix>_hist_stats.txt`,
  `<prefix>_qq_stats.txt`, `<prefix>_fit_measures.txt`, `<prefix>_runs.txt`
- `"curves"`: `<prefix>_curves.pdf` (or `<prefix>_curves/<prefix>_curves_site<ID>.<ext>`)
  and `<prefix>_site_nrms.txt`
- `"nrms"`: `<prefix>_nrms_hist.*` and `<prefix>_nrms_stats.txt`. This method does
  not use `RUN_PATHS`: with `METHODS = ("nrms",)` no run is needed; with other
  methods the histogram is made first.

## Differences to femtic_data_misfit.py

- No `RUN_MODE` and no `single` / `ensemble` word on the command line; this
  script is always an ensemble. For separate single runs use
  `femtic_mod_misfit.py`.
- The settings block is read by `settings()` at the end of the script and handed
  to `femtic_misfit.run_ensemble()`. A typo in a name that looks like a setting
  is reported ("ignoring names that are no setting") instead of being
  passed on silently.
- Nothing else: with the same settings the tables are identical to those of
  `femtic_data_misfit.py` and so are the figures (see "Verification").

## Fit measures

Several measures of data fit are computed for the error-normalized
residuals r, using the routines in `inverse.py` (`nrms`, `r_mae`, `r_med`,
`q95`) plus the mean of r (bias):

| Measure | Definition | Expected for r ~ N(0,1) |
|---------|------------|-------------------------|
| `nrms`  | sqrt(mean(r^2)) | 1 |
| `r_mae` | sqrt(pi/2) * mean(abs(r)) | 1 |
| `r_med` | median(abs(r)) / 0.6745 | 1 |
| `q95`   | 95th percentile of abs(r) | 1.96 |
| `mean`  | mean(r) | 0 |

`r_mae`, `r_med` and `q95` are less sensitive to outliers than `nrms`; if
they stay near their expected values while `nrms` is large, a few outliers
rather than a general misfit are the likely cause. Each is given for both
normalizations: `err` (observed error only, conventional, Baba's RMS1) and
`err+syn` (observed plus synthesized error, RMS2; ensemble only).

Where they appear:

- `<prefix>_fit_measures.txt` (switch `FIT_MEASURES`): pooled over all data
  (`ALL`) and per data type; also printed.
- `<prefix>_crossplot_stats.txt`: per panel (data type / component / part);
  columns with suffix 1 / 2 are the two normalizations (ensemble only).
- `<prefix>_hist_stats.txt`: per band (and pooled), one row per
  normalization, plus `n_out`.

The crossplot and histogram statistics use the same residuals (the RMS1
reference is the ensemble mean, or the `REF_MEMBER` response if set). The
Q-Q table keeps its own robust slope/intercept statistics.

## Site ids: one id per position

Different data types often number the same station differently; in one
real data set the MT stations are 1..48 and the VTF stations 1001..1048
(the "dummy station" trick of the FEMTIC manual). Taken literally, every
data type would be a separate "site" in the per-site table and in the
"curves" figures.

With `SITE_MERGE_BY_POSITION = True` (default) the script therefore checks
the position (`site_x`, `site_y`) of each station of each data type and gives
all rows at the same position -- within `SITE_MERGE_TOL` (default 1 m) --
the `site_id` of the **first occurrence** of that position, in the row order
of the results file (normally the impedance data). VTF 1001 becomes 1, and so
on. Consequences:

- `<prefix>_site_nrms.txt` has one line per position (nRMS over all its
  data types); the new column `also_ids` lists the other ids merged into it.
- "curves": one figure per position, with the impedance (rho, phase) and
  tipper panels together; `CURVES_SITES` (ids, `"worst"`, ...) refers to the
  merged ids; the names from `site.dat` are assigned to the merged ids.
- The crossplot, histogram, Q-Q and fit-measure results do not use site ids
  and are unchanged. Ensemble members are aligned on the original ids
  before the merging.
- The run prints the number of ids and positions and some examples
  (`1001 -> 1`).
- HTF and NMT rows (x / y are not one station position) and rows without a
  finite position keep their ids. If the same number is used for two
  different positions (e.g. MT 2 and a VTF 2 elsewhere), the later one gets a
  fresh id above the largest one, with a warning.
- `False` leaves the ids of the results file as they are.

## Verification

- Syntax and ASCII check of the three new files; `femtic`, `inverse`,
  `data_viz`, `femtic_viz` and `femtic_misfit` import in a clean interpreter
  (`python -I`).
- h5py is not installable in the authoring environment, so
  `femtic.read_results_data` was replaced by a synthetic stand-in (pickle files
  named `results_iterN.h5`; MT, APP_RES_AND_PHS and VTF rows with the VTF
  stations numbered 1001.., 6 sites x 8 frequencies, 3 iterations per run;
  8 ensemble members and 2 single runs). The real `femtic.py`, `inverse.py`,
  `data_viz.py` and `femtic_viz.py` were used otherwise.
- **Equivalence with `femtic_data_misfit.py`** (`RUN_MODE = "ensemble"`, the
  unchanged script run on the same stand-in data and settings): (a) methods
  crossplot, histogram, qq and curves, ensemble of 8 members: 6 text tables
  identical byte for byte, 15 PNG figures (incl. 6 curves figures) identical
  pixel for pixel; (b) method `nrms` alone (from `NRMS_CSV`, 40 members): table
  and figure identical; (c) all five methods together: 7 tables and 16 figures
  identical, console output identical apart from the `femtic_data_misfit:` /
  `femtic_misfit:` message prefix.
- Edge cases: empty `RUN_PATHS` (message, return code 1), only a non-existent
  member (message, return code 1; same as the original), `METHODS = ("nrms",)`
  with no source set (message, return code 0), paths from the command line
  override `RUN_PATHS`, `make_settings` rejects unknown names, `settings()`
  warns about a stray uppercase name.
- **Not run against real `results_iterN.h5` files** (no h5py here). The unit of
  the APP_RES_AND_PHS phase (degrees assumed, `CURVES_APPRES_PHASE_DEG`) and the
  run time of `"curves"` for a large ensemble with many sites are unchecked.
