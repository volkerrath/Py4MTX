# femtic_data_misfit.py

Data-misfit diagnostics for FEMTIC `results_iterN.h5` files (renamed from
`femtic_crossplot.py`, 2026-09-19; run/output handling revised 2026-09-21).

- Author: vrath (DIAS), py4mt
- Code generated by Claude (Anthropic), 2026-09-19, last modified 2026-09-30
  -- AI-generated, review before production use.

## Overview

Four methods, selected with `METHODS` (default: the first three; the fourth,
`"curves"`, is optional and is switched on by adding it to `METHODS`):

1. **crossplot** -- observed vs. calculated scatter plots, one panel per data
   type / component (Re and Im separately for complex types), log10
   frequency as colour, 1:1 line, n and nRMS per panel.
2. **histogram** -- normalized-residual histograms in frequency (or period)
   bands, after Baba (2023). One figure per data type (or per data type and
   component, `HIST_BY_COMPONENT`); first panel pools all bands, then one
   panel per band. Default: 2 bands per decade (`HIST_BANDS_PER_DECADE`),
   `HIST_BAND_AXIS = "frequency"` or `"period"`; bands are anchored at
   whole decades; bands with fewer than `HIST_MIN_N` values are skipped.
3. **qq** -- normal Q-Q plots of the same normalized residuals, in the same
   kind of frequency/period bands (`QQ_*` settings, default 2 per decade,
   pooled panel first). Per panel: sample quantiles vs. theoretical N(0,1)
   quantiles at plotting positions (i - 0.5)/n; black line = ideal N(0,1)
   (calibrated errors); red dashed = line through the first and third
   quartiles, whose slope is a robust scale (slope > 1: misfit larger than
   the stated errors, < 1: errors overestimated) and whose intercept is a
   bias; gray band = pointwise confidence envelope (`QQ_CONFIDENCE`,
   default 95 %) around the quartile line, from the asymptotic standard
   error of order statistics, se_i = sqrt(p_i (1 - p_i) / n) / phi(z_i).
   The envelope therefore judges the Gaussian shape irrespective of scale
   and bias; the slope/intercept report those. In ensemble mode the dots
   are RMS2-normalized with the RMS1-normalized dots in orange (slope1 /
   slope2 in the table); in single mode only the conventional residuals
   are shown. The envelope is pointwise, not simultaneous, so some points
   outside it are expected (`out%` in the statistics table). With
   `QQ_EQUAL_AXES = True` both axes get the same range (at most
   +/- `QQ_LIMIT`) and the panels are square, so the ideal line is at 45
   degrees; the default (False) uses a common y range only.

4. **curves** (optional) -- response curves per site: the observed data
   (markers with error bars or shading) against the calculated response,
   drawn with the `data_viz` plotters (`add_rho`, `add_phase`, `add_tipper`,
   `add_pt`). One figure per site, one panel per entry of `CURVES_WHAT`.
   Details in the section "Response curves" below.

## Response curves (method "curves")

Enable with `METHODS = ("crossplot", "histogram", "qq", "curves")` (or just
`("curves",)`). Requires `data_viz.py` on the path (`femtic_viz.py` is used
if importable, only for its component-marker convention; a local fallback is
built in). Without "curves" in `METHODS` nothing here is imported or run.

**What is drawn.** For every selected site one figure with one panel per
quantity of `CURVES_WHAT`:

| Panel | data_viz plotter | Series (colour) | Built from data types |
|-------|------------------|-----------------|-----------------------|
| `"rho"` | `add_rho` | `CURVES_COMPS`, e.g. xy blue, yx red | MT / NMT2 (from Z), APP_RES_AND_PHS |
| `"phase"` | `add_phase` | same | MT / NMT2, APP_RES_AND_PHS |
| `"tipper"` | `add_tipper` | Re/Im of Tzx, Tzy | VTF |
| `"pt"` | `add_pt` | PTxx, PTxy, PTyx, PTyy | PT |

A panel is left out for a site that has no data for it; HTF and NMT have no
data_viz plotter and are skipped (reported once).

**Single run.** Observed data (markers: `CURVES_OBS_ERRORS` = `"bar"`
error bars, `"shade"` shaded band, or `"none"`) and the calculated response
as a line.

**Ensemble.** The M members' calculated responses are shown according to
`CURVES_ENS_MODE`, so that a large ensemble stays readable:

| Mode | What it draws | Sensible for |
|------|---------------|--------------|
| `"curves"` | every member as a thin transparent line (opacity from the number of curves, `CURVES_MEMBER_ALPHA`); at most `CURVES_SUBSAMPLE` members, randomly chosen if there are more | up to a few tens of members |
| `"density"` | per-period density of all member curves: every member curve is interpolated (in log period and, for rho, log10 y) onto `CURVES_DENSITY_NX` grid points, binned in `CURVES_DENSITY_NY` y-bins, and drawn in the series colour with opacity = fraction of members in the bin (`CURVES_DENSITY_GAMMA` < 1 lifts sparse regions) | hundreds of members |
| `"bands"` | percentile envelopes `p ... 100-p` for each `p` in `CURVES_BAND_PCT` (default 5 and 25 -> 5-95 % and 25-75 %) | any M >= 3 |
| `"auto"` (default) | `"curves"` for M <= `CURVES_MAX_CURVES` (50), else `"density"` | |

Modes can be combined with `+`, e.g. `"density+bands"` or
`"density+curves"`. The ensemble median (`CURVES_MEDIAN`, on by default) and
the observed data (mean over members, as in the other methods, see
`ENSEMBLE_OBS`) are drawn on top.

**Site selection.** `CURVES_SITES`: `None` = all sites; an integer N = N sites
chosen by `CURVES_SITE_ORDER` (`"even"` = evenly spread over the site list,
default; `"id"` = the first N; `"worst"` / `"best"` = largest / smallest site
nRMS); a list = exactly these sites, given as `site_id` values and/or site names. `CURVES_MAX_SITES` caps the
number of figures. The site nRMS (real and imaginary parts, conventional
normalization) is shown in each figure title and written for all sites to
`<prefix>_site_nrms.txt`, which is a quick way to find the sites worth
looking at (`site_x`/`site_y` are printed as stored in the results file).

**Site names.** The results file has only the integer `site_id`; names come
from the `site.dat` written by `mt_make_sitelist.py` (columns name, lat, lon,
elev, sitenum, easting, northing), read with `femtic.read_site_dat`.
`CURVES_SITE_DAT = "auto"` (default) looks for `site.dat` in the results
directory and up to two levels above it (so an ensemble root works); a path
can be given instead, `None` switches names off. The mapping is
`site_id = sitenum + CURVES_SITE_ID_OFFSET` (offset 0 by default, i.e.
`sitenum` = `site_id`; `mt_make_sitelist.py` numbers sites from 0 in sorted
file-name order). The number of matched ids is printed, with a warning if not
all match -- please check this once against a real run, since I could not
confirm how FEMTIC numbers `site_id`. Names appear in the figure titles, in the
per-site file names and in `<prefix>_site_nrms.txt`.

**Output.** With `".pdf"` in `PLOT_FORMATS` and `CURVES_MULTIPAGE = True`
(default): one file `<prefix>_curves.pdf`, one page per site. Other formats
(and `.pdf` with `CURVES_MULTIPAGE = False`): one file per site,
`<prefix>_curves/<prefix>_curves_site<ID>.<ext>`.

**Axes.** `CURVES_INVERT_X = True` keeps the `data_viz` orientation (period
decreasing to the right); `False` gives period increasing to the right.
`CURVES_PERIOD_LIM` and `CURVES_YLIM` (a dict keyed by panel, either bound may
be `None`) fix the limits; useful when a few huge error bars blow up the
autoscaling. `CURVES_LEGEND_LOC = "below"` puts each legend under its panel
(default; also fast with density); any matplotlib `loc` string works, `None`
switches legends off. Avoid `"best"` together with density: matplotlib then
needs seconds per panel to place the legend.

### Notes and assumptions (please check)

- **Same conventions as data_viz.** rho_a = |Z|^2 / (mu0 omega) with Z in SI
  ohm as stored by FEMTIC (identical to `data_viz.datadict_to_plot_df` applied
  to Z scaled to mV/km/nT), phase = atan2(Im Z, Re Z), and the errors of rho_a
  and phase from the complex modulus hypot(re_err, im_err) of the errors of Z.
  This was checked numerically against `datadict_to_plot_df` (agreement to
  machine precision for rho, phase and both errors).
- **Phase branch.** The calculated phase is put on the branch of the observed
  phase (difference wrapped to +-180 degrees). Without this, members whose yx
  phase (close to -180 degrees) crosses the +-180 boundary jump by 360 degrees,
  which ruins medians and densities. The observed phase itself is plotted as
  stored, so panels may extend slightly beyond +-180.
- **APP_RES_AND_PHS** values are drawn as stored: rho in ohm.m, phase in
  degrees (`CURVES_APPRES_PHASE_DEG = False` if they are in radians). I could
  not confirm the unit from the code base; please check it against a real file.
- **Observed data in an ensemble** are the mean over members
  (`ENSEMBLE_OBS = "mean"`), or those of the first member with `"first"`.
- **Median and percentiles** are taken over the members' derived quantities
  (rho_a, phase, ...), not over Z.
- **Density** is a display of the spread of the interpolated member curves in
  the (log period, y) plane; it is not a probability density of the data, and
  the bin heights depend on `CURVES_DENSITY_NY`. The y range of the bins is the
  0.25-99.75 percentile range of the curves (plus 5 %), so extreme outliers are
  not shown in the density (they still enter the percentile bands).
- Every member's calculated response is held in memory as an (M, rows)
  array (`cal_re_m`, `cal_im_m` in the dataset); this is small next to the
  raw results files but scales with M x number of data rows.
- The plotters are called once per drawn series (and once per member for
  `"curves"`); `data_viz` toggles the x-axis direction on every call and
  colours error shading from the colour cycle, so the script restores the
  axis direction after each call and recolours the shading. Error shading is
  therefore only done for the observed data.

## Fit measures

Several measures of data fit are computed for the error-normalized
residuals r, using the routines in `inverse.py` (`nrms`, `r_mae`, `r_med`,
`q95`) plus the mean of r (bias):

| Measure | Definition | Expected for r ~ N(0,1) |
|---------|------------|-------------------------|
| `nrms`  | sqrt(mean(r^2)) | 1 |
| `r_mae` | sqrt(pi/2) * mean(abs(r)) | 1 |
| `r_med` | median(abs(r)) / 0.6745 | 1 |
| `q95`   | 95th percentile of abs(r) | 1.96 |
| `mean`  | mean(r) | 0 |

`r_mae`, `r_med` and `q95` are less sensitive to outliers than `nrms`; if
they stay near their expected values while `nrms` is large, a few outliers
rather than a general misfit are the likely cause. Each is given for both
normalizations: `err` (observed error only, conventional, Baba's RMS1) and
`err+syn` (observed plus synthesized error, RMS2; ensemble only).

Where they appear:

- `<prefix>_fit_measures.txt` (switch `FIT_MEASURES`): pooled over all data
  (`ALL`) and per data type; also printed.
- `<prefix>_crossplot_stats.txt`: per panel (data type / component / part);
  columns with suffix 1 / 2 are the two normalizations (ensemble only).
- `<prefix>_hist_stats.txt`: per band (and pooled), one row per
  normalization, plus `n_out`.

The crossplot and histogram statistics use the same residuals (the RMS1
reference is the ensemble mean, or the `REF_MEMBER` response if set). The
Q-Q table keeps its own robust slope/intercept statistics.

Two run modes (`RUN_MODE`, or first command-line word):

- **single** -- a list of runs (`RUN_PATHS`: run directories, results files,
  or glob patterns), each processed **on its own**; they do *not* form an
  ensemble, and each run gets its own figures and tables. A run that cannot
  be read is reported and skipped; the exit code is then 1. For a run
  directory (all `results_iter*.h5` searched) or a results file,
  `ITERATION = "best"` (default) picks the file with the
  smallest overall error-normalized RMS of its `/data` rows (real and
  imaginary parts; imaginary part omitted for real-valued types);
  `"last"` or an integer are also accepted (ignored for a results file
  given directly). The chosen iteration and its RMS are printed and written
  to `<prefix>_runs.txt`.
- **ensemble** -- all entries of `RUN_PATHS` together form one ensemble; the
  chosen iteration of each run is one member (M members). Rows are matched
  by (datatype, site_id, component, frequency); rows missing in any member
  or with a non-finite calculated value in any member are dropped.

## Usage

    python femtic_data_misfit.py                          # config block
    python femtic_data_misfit.py single   ./run01/ ./run02/   # separately
    python femtic_data_misfit.py ensemble "./ens/member_*/"

`femtic.py` (and `ensembles.py`, which it imports) and `inverse.py` (fit
measures; it imports `aniso`) must be importable; if
`PY4MTX_ROOT` is set, `$PY4MTX_ROOT/py4mt/modules` and `.../scripts` are
added to `sys.path`. Method `"curves"` additionally needs `data_viz.py`
(numpy, pandas, matplotlib only) and can use `femtic_viz.py` if importable.

Output location: `OUT_DIR = None` (default) writes into the run directory
-- single: the directory of each chosen results file; ensemble: the common
parent directory of the member directories. A string forces one directory
for everything (file names stay distinct through the prefix).

Output files, prefix = `<run>_iter<N>` (single) or `ensemble_M<M>`
(ensemble). `OUT_PREFIX` replaces it; with several singles it is prepended
instead (`<OUT_PREFIX>_<run>_iter<N>`) so runs do not overwrite each other:
`<prefix>_crossplot_<DATATYPE>.*`, `<prefix>_hist_<GROUP>.*`,
`<prefix>_qq_<GROUP>.*`, `<prefix>_crossplot_stats.txt`,
`<prefix>_hist_stats.txt`, `<prefix>_qq_stats.txt`,
`<prefix>_fit_measures.txt`, `<prefix>_runs.txt`; with method `"curves"`:
`<prefix>_curves.pdf` (or `<prefix>_curves/<prefix>_curves_site<ID>.<ext>`)
and `<prefix>_site_nrms.txt`.

## Method (Baba 2023)

Baba (2023) proposes normalizing the residuals by both the observed and the
synthesized standard error, with M syntheses of the same model (Eqs. 10-14):

    mu      = (1/M) sum_j Z_j                          (complex mean)
    sigma   = sqrt( 1/(M-1) sum_j |Z_j - mu|^2 )       (complex modulus)
    eps_syn = sigma / sqrt(M)
    RMS1    = sqrt( 1/(2N) sum |Zobs - Zsyn|^2 / eps_obs^2 )
    RMS2    = sqrt( 1/(2N) sum |Zobs - mu|^2 / (eps_obs^2 + eps_syn^2) )

The histograms follow the paper's Fig. 10a: bars = normalized residuals,
red line = N(0, RMS^2), blue dashed lines = +/- RMS. In ensemble mode the
bars use the RMS2 normalization and the RMS1 histogram is added as an
orange step outline; in single mode (M = 1, eps_syn = 0) RMS2 equals RMS1
and only the conventional histogram is drawn.

### Assumptions and generalizations (please check)

- **Ensemble members play the role of Baba's M syntheses.** In the paper
  the M calculations are the same model discretized in M rotated coordinate
  systems, all expressed in a common coordinate system. For an ensemble of
  different models (e.g. RTO members) sigma is model spread, not
  forward-calculation uncertainty; the formulas are applied unchanged, but
  interpret RMS2 accordingly.
- **Per-part errors.** FEMTIC gives `re_err` and `im_err`; each real /
  imaginary part is normalized by its own error (the paper uses one
  eps_obs per complex element). eps_syn (from the complex modulus) is shared
  by both parts. For real-valued data types (APP_RES_AND_PHS, PT, ...)
  the formulas reduce to one real part per datum.
- **Observed data in an ensemble.** `ENSEMBLE_OBS = "mean"` averages observed
  values and errors over members (RTO-perturbed data average back to the
  original); `"first"` uses the first member.
- **RMS1 reference.** `REF_MEMBER = None` uses the ensemble mean as the
  calculated response for RMS1 (so RMS1 and RMS2 differ only by eps_syn);
  an integer uses that member's response, as Baba used one model.
- **Best iteration** is determined here from the `/data` rows only (no
  distortion, no regularization term); it may differ from FEMTIC's own
  convergence log.
- Crossplots in ensemble mode show observed vs. the ensemble-mean response.

### Changelog (2026-09-21d) --- PLOT_FORMATS fix

Claude Sonnet 5 (Anthropic), 2026-09-21: `PLOT_FORMATS = (".pdf")` is the
string `".pdf"`, not a tuple; the save loop iterated its characters (".",
"p", "d", "f") and, since none is a valid extension, matplotlib wrote four
identical PNG files per figure named `<stem>.png`, `<stem>p.png`,
`<stem>d.png` and `<stem>f.png` (and no PDF). `_save()` now treats a string
as one format, adds a missing leading dot and passes the format explicitly,
so an unsupported extension raises an error instead of silently producing a
PNG. The default is now written `(".pdf",)`.
